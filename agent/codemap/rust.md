## The R3 screen framework (R3.1a)

How a rebuilt screen paints pixel-identical to the goldens:

1. Compute rects from the terminal size with `screens::pane_layout(x0, y0, x1, y1, row_heights, col_widths)`; `Zoom`/`zoom_rect` collapses the grid for a zoomed pane. Never hardcode coordinates (D2).
2. Paint each pane into the golden cell model: `Screen::themed(palette, w, h)` (dark default), `screen.pane(...)`, `screen.text/put/fill`, `screen.price_chart(...)`, plus the `components.rs` widgets (`ActionChip::draw_screen`, `KeyGrid::draw_screen`, `Scrollbar::draw_screen`, ...). Painters write **dark** token hexes; `Screen::put` remaps them for `Palette::Light` (see `theme.rs::LIGHT_REMAP`).
3. Blit with `screen::blit(frame, &screen, area)` — the live frame is then cell-for-cell what the harness diffs.
4. Keys: implement `delta_tui::Screen` (`name`, `handle_key → Option<Action>`, `update`, `draw`); the app routes bus actions and shell modals (Go/help/palette take keys first, as Textual modals stop propagation).
5. Modals: `resolve_modal_base()` + `dim()` before drawing the dialog (`dialog_frame` paints the surface-chrome box; `hint_markup`/`centred_line` for title/hint rows).

## Conventions

- Datetimes: naive UTC (`NaiveDateTime`), stored as `YYYY-MM-DD HH:MM:SS.ffffff` — byte-compatible with SQLModel.
- IDs: `stable_id` sha256 over NUL-joined parts; stored hashes must stay Python-compatible.
- Checks: `cargo fmt --all`, `cargo clippy --all-targets -- -D warnings`, `cargo test --workspace`.
- Provider tests run against `wiremock` — no live LLM/network calls, ever.
- Findings: `docs/rewrite/findings/rust-core.md`, `docs/rewrite/findings/rust-llm.md`.
